# Офисный и разработческий сленг (шпаргалка)

> Не привязано к коду PM Meetup: общий словарь для переписки и созвонов.

Сборник частых слов и выражений в IT и офисе: русские, англицизмы и «гибриды». Значения могут чуть отличаться в разных командах — ориентир по общему употреблению.

---

## 1. Встречи, процессы, управление

| Слово / фраза | Что обычно имеют в виду |
|----------------|-------------------------|
| **синк** (sync) | Короткая синхронизация: статусы, планы, блокеры |
| **стендап** (stand-up) | Ежедневная встреча 10–15 мин: что сделал / делаю / мешает |
| **дейли** (daily) | То же, что стендап |
| **ретро** (retrospective) | Разбор итерации: что улучшить в процессе |
| **планирование** / **планинг** | Оценка задач, выбор на спринт |
| **груминг** / **рефайнмент** (grooming / refinement) | Уточнение и декомпозиция задач в бэклоге |
| **спринт** (sprint) | Фиксированный период (часто 1–2 недели) с набором задач |
| **квартальное планирование** | Планы на квартал (OKR, цели) |
| **бэклог** (backlog) | Список задач / идей, ещё не в работе или в очереди |
| **скоуп** (scope) | Объём работ: что входит в задачу / релиз |
| **скоуп крип** (scope creep) | Неконтролируемое разрастание объёма |
| **таймбокс** (timebox) | Жёстко ограниченное время на активность |
| **таймлайн** (timeline) | Сроки и этапы по времени |
| **милстоун** (milestone) | Веха, контрольная точка проекта |
| **дедлайн** (deadline) | Крайний срок |
| **эскалация** | Передача проблемы выше по иерархии |
| **блокер** | То, что мешает продолжать работу |
| **депенденси** (dependency) | Зависимость от другой задачи / команды / сервиса |
| **рейдж** (re-prioritization) | Перестановка приоритетов (часто срочная) |
| **онбординг** (onboarding) | Ввод нового сотрудника в процессы и доступы |
| **оффбординг** (offboarding) | Выход: закрытие доступов, передача дел |
| **хэндовер** (handover) | Передача зоны ответственности |
| **кик-офф** (kick-off) | Стартовая встреча проекта / этапа |
| **воркшоп** (workshop) | Рабочая сессия, часто с практикой |
| **брейншторм** (brainstorm) | Мозговой штурм |
| **фасилитация** | Ведение встречи нейтральным модератором |
| **фоллоу-ап** (follow-up) | Договорённости после встречи, напоминание |
| **экшн айтемы** (action items) | Конкретные действия после встречи |
| **минутки** / **митинг нотес** (meeting notes) | Запись итогов встречи |
| **асайн** / **назначить** (assign) | Назначить ответственного на задачу |
| **апрув** (approve) | Согласование (код, бюджет, дизайн) |
| **стейкхолдер** (stakeholder) | Заинтересованная сторона (заказчик, продукт, юристы) |
| **овнер** (owner) | Владелец направления / продукта / задачи |
| **чемпион** (champion) | Тот, кто продвигает идею внутри компании |
| **эдвокат** (advocate) | Сторонник решения / технологии |

## 2. Задачи, трекеры, «гибкие» термины

| Слово | Смысл |
|--------|--------|
| **тикет** / **таска** / **issue** | Единица работы в Jira / YouTrack / GitHub |
| **эпик** (epic) | Крупная тема из нескольких задач |
| **стори** (user story) | Пользовательская история: кто / что / зачем |
| **сабтаска** (sub-task) | Подзадача |
| **баг** (bug) | Дефект, ошибка в продукте |
| **фича** (feature) | Новая функциональность |
| **спайк** (spike) | Исследовательская задача: «посмотреть, сколько займёт» |
| **техдолг** (tech debt) | Долг качеству: отложенный рефакторинг, старые библиотеки |
| **рефакторинг** | Улучшение структуры кода без смены поведения |
| **хотфикс** (hotfix) | Срочный патч в продакшен |
| **релиз** (release) | Выпуск версии продукта |
| **роллбек** / **откат** (rollback) | Возврат к предыдущей стабильной версии |
| **канбан** | Доска с колонками «в работе / готово» |
| **WIP** (work in progress) | Ограничение «сколько задач одновременно в работе» |
| **DoD** (definition of done) | Критерии «задача считается сделанной» |
| **AC** (acceptance criteria) | Критерии приёмки |

## 3. Разработка, репозиторий, деплой

| Слово | Смысл |
|--------|--------|
| **репо** (repo) | Репозиторий кода |
| **ветка** (branch) | Линия разработки в Git |
| **мерж** (merge) | Слияние веток |
| **ребейз** (rebase) | Перенос коммитов на другую базу |
| **конфликт** (merge conflict) | Несовместимые изменения при слиянии |
| **ПР** / **МР** (PR / MR) | Pull request / merge request — запрос на слияние |
| **ревью** (code review) | Проверка кода коллегой |
| **коммит** (commit) | Снимок изменений в Git |
| **пуш** (push) | Отправка коммитов на сервер |
| **пулл** (pull) | Получение изменений с сервера |
| **форк** (fork) | Копия репозитория |
| **клон** (clone) | Локальная копия репозитория |
| **черри-пик** (cherry-pick) | Перенос отдельных коммитов |
| **деплой** (deploy) | Выкладка на сервер / в прод |
| **стейджинг** (staging) | Предпродакшен-среда для проверки |
| **прод** / **продакшн** (prod / production) | Боевая среда для пользователей |
| **дев** / **девелоп** (dev) | Разработческая среда |
| **локалка** | Локальная машина разработчика |
| **сид** / **фикстуры** (seed / fixtures) | Тестовые данные в БД |
| **миграция** (migration) | Изменение схемы БД через код |
| **сборка** / **билд** (build) | Компиляция / упаковка артефакта |
| **артефакт** (artifact) | Результат сборки (jar, docker image) |
| **пайплайн** / **CI** | Автоматические проверки и деплой |
| **линтер** (linter) | Инструмент проверки стиля кода |
| **юнит-тесты** (unit tests) | Тесты отдельных модулей |
| **интеграционные тесты** | Проверка связок компонентов |
| **e2e** (end-to-end) | Сквозные тесты как у пользователя |
| **регрессия** | Повторное появление старого бага |
| **смоук** (smoke test) | Быстрая проверка «жив ли критичный функционал» |
| **стаб** (stub) / **мок** (mock) | Подмена зависимости в тестах |
| **фича-флаг** (feature flag) | Включение фичи без нового деплоя |
| **канареечный деплой** (canary) | Выкатка на часть пользователей |
| **блю-грин** (blue-green) | Две среды для безопасного переключения |
| **даунтайм** (downtime) | Время недоступности сервиса |
| **аптайм** (uptime) | Доля времени работы |
| **алёрт** / **пейджер** (alert / pager) | Оповещение об инциденте |
| **постмортем** (postmortem) | Разбор инцидента после фикса |
| **инцидент** | Сбой, требующий реакции |
| **Сев1 / Сев2** (severity) | Уровни критичности инцидента |

## 4. Архитектура и инфраструктура (часто в разговоре)

| Слово | Смысл |
|--------|--------|
| **монолит** (monolith) | Одно крупное приложение |
| **микросервисы** | Много мелких сервисов |
| **API** | Интерфейс для обмена данными между системами |
| **эндпоинт** (endpoint) | Конкретный URL / метод API |
| **контракт** | Соглашение о формате API между командами |
| **бэк** / **бэкенд** (backend) | Серверная часть |
| **фронт** / **фронтенд** (frontend) | Клиентская часть (браузер, приложение) |
| **фулстек** (fullstack) | И бэк, и фронт |
| **SSR** | Server-side rendering — HTML с сервера |
| **CSR** | Client-side rendering — рендер в браузере |
| **SSG** | Static site generation |
| **кэш** (cache) | Быстрое хранилище копии данных |
| **очередь** (queue) | Асинхронная обработка задач |
| **брокер сообщений** | RabbitMQ, Kafka и т.п. |
| **контейнер** (Docker) | Изолированное окружение приложения |
| **оркестратор** | Kubernetes, Docker Swarm |
| **под** (pod) | Минимальная единица в K8s |
| **секрет** (secret) | Пароли/ключи вне кода |
| **енв** (.env) | Переменные окружения |
| **реплика** | Копия сервиса для нагрузки или отказоустойчивости |
| **шард** (shard) | Горизонтальное разбиение данных |
| **репликация** | Копирование данных между узлами |
| **бэкап** (backup) | Резервная копия |
| **DR** (disaster recovery) | План восстановления после катастрофы |

## 5. Офис, коммуникация, «соцкапитал»

| Слово | Смысл |
|--------|--------|
| **пинг** (ping) | Написать, напомнить, привлечь внимание |
| **фоллоу-ап** | Напоминание по договорённости |
| **фидбек** (feedback) | Обратная связь |
| **вэлью** (value) | Ценность для бизнеса / пользователя |
| **инсайт** (insight) | Нетривиальное понимание из данных / обсуждения |
| **хайлайт** (highlight) | Главное из отчёта / встречи |
| **аутрич** (outreach) | Выход на внешние контакты |
| **он-сайт** / **офф-сайт** | Встреча в офисе / выездная |
| **WFH** (work from home) | Удалёнка из дома |
| **хибрид** (hybrid) | Частично офис, частично дом |
| **асап** (ASAP) | Как можно скорее |
| **EOD** (end of day) | К концу рабочего дня |
| **COB** (close of business) | К закрытию дня (часто по часовому поясу офиса) |
| **OOO** (out of office) | Вне офиса / в отпуске (автоответчик) |
| **PTO** (paid time off) | Оплачиваемый отпуск |
| **деадпул** (dead pool) — шутл. | Проект «на грани», часто юмор |
| **бенч** (bench) | Сотрудник без проекта в консалтинге |
| **биллабл** (billable) | Часы, которые можно выставить клиенту |
| **нон-биллабл** | Внутренние часы (обучение, админ) |

## 8. Шутливое и разговорное (осторожно с контекстом)

| Выражение | Часто значит |
|-----------|----------------|
| **залить** | Запушить в репозиторий / задеплоить |
| **отстрелить** | Быстро выпустить фикс |
| **прогреть** | Прогнать кэш, прогрев сервиса |
| **положить прод** | Вывести прод из строя (ошибка) |
| **легаси** (legacy) | Старый код, с которым неприятно работать |
| **костыль** | Временное некрасивое решение |
| **велосипед** | Изобретение своего вместо готовой библиотеки |
| **оверинжиниринг** | Чрезмерное усложнение |
| **бойлерплейт** (boilerplate) | Однотипный шаблонный код |
| **дублирование** | Copy-paste логики |
| **магия** | Непонятное автоматическое поведение |
| **зомби-процесс** | Подвисший процесс |
| **утечка памяти** (memory leak) | RAM растёт без освобождения |
| **флейк** (flaky test) | Тест то проходит, то падает |
| **грин** (green build) | Сборка без ошибок |
| **ред** (red build) | Сборка с ошибками |

## 9. Сокращения в переписке (англ.)

- **LGTM** — looks good to me (ок с моей стороны)  
- **SGTM** — sounds good to me  
- **FYI** — for your information  
- **ETA** — estimated time of arrival / когда ожидать  
- **TBD** — to be determined  
- **TBC** — to be confirmed  
- **WIP** — work in progress  
- **IMO / IMHO** — по моему мнению  
- **TL;DR** — кратко в одном абзаце  
- **PTAL** — please take a look  
- **AFAIK** — as far as I know

## 10. Как пользоваться этим файлом

- Для **новичка**: не нужно знать всё — достаточно базы (спринт, тикет, ревью, деплой, блокер).  
- Для **письма заказчику** лучше заменять жаргон нейтральными формулировками («сроки», «согласование», «приёмка»).  
- Значения **плавают** между командами — при сомнении лучше переспросить.
