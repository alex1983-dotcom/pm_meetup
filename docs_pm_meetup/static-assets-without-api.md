# Постоянные картинки без участия API

Соглашение для бэкенда и фронта: **картинки, которые не приходят из REST** (не `ImageField` в JSON, не `media`), а живут в репозитории и меняются только с релизом кода.

Третий путь — загрузки в админке и URL в API (`/media/...`) — здесь **не** описан; он для редактируемого контента.

---

## Вариант 1 — Django: каталог `static/` у корня репозитория

**Идея:** файлы лежат в репозитории в каталоге `static/` (см. `STATICFILES_DIRS` в `config/settings/base.py`), при деплое попадают в `staticfiles` через `collectstatic`, отдаются по префиксу **`/static/...`**.

**Плюсы**

- Один источник правды с остальной Django-статикой (админка, общие ассеты сайта).
- В проде с nginx тот же префикс `/static/`, кэширование на уровне веб-сервера.

**Минусы для связки с CRA**

- В разработке фронт обычно на **`http://localhost:3000`**, API и Django — на **`http://localhost:8000`** (см. `docker-compose.yml`). Путь **`/static/...` относительно `localhost:3000`** сам по себе **не** попадёт на Django, если явно не проксировать `/static` через dev-server или не использовать **абсолютный** URL до бэкенда, например `http://localhost:8000/static/...`.

**Что обсудить с фронтом**

- Базовый URL для статики в деве: env вроде `REACT_APP_STATIC_ORIGIN=http://localhost:8000` или прокси `/static` → `web:8000`.
- В проде (образ nginx + Django из репо) префикс `/static/` уже обслуживается; при SPA за тем же доменом достаточно **`/static/images/foo.png`** в разметке.

**Важно:** REST API **не** отдаёт список файлов из `static/`; путь к конкретному файлу договаривается командой (документ, константа на фронте, slug в блоках страницы и т.п.).

---

## Вариант 2 — React (CRA): `frontend/public/` или импорт из `frontend/src`

**Идея:** ассеты лежат рядом с фронтом. Либо **`public/`** (файлы копируются в корень сборки как есть), либо **`import img from './...'`** в `src/` (webpack даёт URL с хэшем в имени).

**Плюсы**

- В деве картинка с того же origin, что и приложение (**`localhost:3000`**), без отдельной настройки прокси для статики.
- Удобно для чисто UI-ресурсов: иконки, иллюстрации, фоны, которые не должны настраиваться из админки.

**Минусы**

- Логически это «слой фронта»; бэкенд о них не знает.
- В прод-сборке из `Dockerfile.nginx.prod` у CRA задан `PUBLIC_URL=/react-assets`; публичные файлы попадают в билд под этим префиксом — фронту нужно использовать **`%PUBLIC_URL%`** в `index.html` или учитывать префикс в коде, если жёстко зашивать пути.

**Что обсудить с фронтом**

- Какие ассеты считаем **только UI** → вариант 2.
- Нужен ли общий каталог/именование (например `public/images/...`) для порядка в репозитории.

---

## Краткое сравнение (для встречи)

| | Вариант 1 (`static/` + `/static/`) | Вариант 2 (`public/` / `src`) |
|---|-------------------------------------|--------------------------------|
| Где в репо | Корень: `static/` | `frontend/public/` или `frontend/src/` |
| Участие API | Нет | Нет |
| Дев (CRA :3000) | Нужен явный origin или прокси для `/static` | Обычно «просто работает» с того же хоста |
| Типичное применение | Общие ассеты сайта вместе с Django | Декоративные картинки интерфейса SPA |

После договорённости имеет смысл зафиксировать в задаче/ADR: *какой вариант для каких экранов* и *как в деве задаётся базовый URL для варианта 1*.
